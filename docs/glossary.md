# Glossary — MediKiosk

**ABDM** — Ayushman Bharat Digital Mission.

**ABHA** — Health account/identifier concept used within ABDM. The prototype should not imply a demo field is a verified production identity.

**ASR** — Automatic Speech Recognition; speech-to-text.

**TTS** — Text-to-Speech.

**HIS** — Hospital Information System.

**EMR/EHR** — Electronic Medical/Health Record.

**FHIR** — Standardized healthcare data-exchange resource/API model used at the integration boundary.

**HPI** — History of Present Illness.

**SOCRATES** — Common mnemonic for structured pain history (site, onset, character, radiation, associations, timing, exacerbating/relieving factors, severity).

**Red flag** — A predefined symptom/fact pattern that should prompt priority clinical assessment. It is not itself a diagnosis.

**Clinical normalization** — Mapping patient wording into a standard internal clinical concept/field.

**Provenance** — Information describing where a fact came from and how it was produced.

**Verification status** — Whether data is patient-reported, AI/document-extracted and unverified, or clinician-verified.

**Canonical data** — The structured internal representation treated as the system source of truth.

**Modular monolith** — A single deployable backend organized into clear internal modules rather than independently deployed microservices.

**Adapter** — A code boundary that hides provider-specific APIs, allowing mocks or alternate providers.

**SIH** — Smart India Hackathon.
