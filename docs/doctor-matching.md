# Doctor matching (prototype)

The versioned `ai/doctor_matching/compatibility_v1.json` is the only specialty compatibility source. Only active, accepting doctors with an active membership at the selected facility, an explicitly eligible primary or declared subspecialty, and an availability other than `OFF_DUTY` reach ranking. `BUSY` remains eligible; `AVAILABLE` ranks higher. No implicit General Medicine fallback exists. For routine pre-arrival journeys, MediRoute recommends only facilities where this same eligibility check finds at least one selectable doctor; directory or availability changes invalidate the saved facility result.

For synthetic end-to-end verification, run `scripts/start-e2e.ps1`. It uses only the ignored `.runtime/e2e.sqlite`, applies local Alembic migrations, seeds deterministic demo facilities/doctors, and starts localhost ports 8010/5175 with mock providers. `-Reset` removes only that dedicated SQLite file. This is separate from the normal Supabase launcher; never use it for real patient information. `scripts/verify-phase4-e2e.py` exercises the live local API journeys.

The maximum score is **84**: specialty 35, matching complaint expertise 20, availability 10, continuity 10, experience 6, and preferred language 3. Experience is capped at 20 years for scoring. Continuity counts only previously **confirmed** sessions assigned to the same doctor, two points per session up to five. Ties break by doctor ID. These are prototype ranking weights, not clinical evidence or a diagnosis.

Emergency routing bypasses normal doctor recommendations. A patient explicitly selects from the persisted eligible set; the selection is stored on the session. The match signature includes the clinical route, current facility recommendation, selected facility, directory state, and protocol version. A changed signature generates a new match and invalidates the previous session selection. Repeated requests with unchanged inputs reuse the saved result.
